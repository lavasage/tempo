### 实现

- 与前端口径对齐：缓冲为一次间隔（`b.start < new.end + gap and b.end > new.start − gap`）；取消记录跳过校验且不占位；只改状态不重新校验，保证规则调整后仍能收尾历史课程；跨夜窗口 `end_minute ≤ start_minute` 顺延一天。
- `supabase/tests/`：PGlite（WASM Postgres 18.6）+ `auth.uid()` shim，按教练切换 authenticated 角色；`npm run test:db` 执行。

## 2026-11-11 — Milestone 4（B 客户端）
范围：把前端接上异步远端仓库与邮箱登录。未连真实 Supabase（无凭据），远端路径只有单测覆盖；本地演示路径行为不变。

### 实现
- `0004_client.sql`：`snapshot()` 一次返回本账号的教练、学员、类型、课程、评价、事件与可用性；`save_availability()` 在同一事务里替换设置、规则与临时不可约，并拒绝未登录与越界缓冲。
- `src/services/remote/`：`config` 仅在 URL 与 anon key 同时存在时启用远端；`session` 封装 GoTrue 登录/注册/续期/退出并持久化会话；`client` 封装 PostgREST 与 RPC，把 23505、42501、401 等翻成中文；`mapping` 负责分钟↔时钟、快照↔`Database`、可用性↔RPC 参数；`repository` 提供异步写入方法。
- `stores/auth.ts`：本地模式视为已登录；远端模式初始化时续期，过期则清会话。`views/Login.vue` 提供登录/注册切换与错误提示。
- `stores/sync.ts`：顺序推送队列，失败停住并暴露 `pending`/`error`/`retry`；推送内容按实体拆分，课程创建用课程 id 作 `p_request` 幂等键。
- `stores/tempo.ts`：远端模式改用内存仓库，不读也不写 `tempo.v1`；新增 `hydrated`、`replaceData`、`ensureDefaultTypes`；每次成功提交后向队列投递对应操作。本地模式分支与原来一致。
- `main.ts`：新增 `/login` 与路由守卫——远端未登录只能到登录页，刷新时补拉快照；本地模式访问 `/login` 直接回首页。
- `App.vue`：登录页独立渲染不套侧栏；业务视图要求 `hydrated`；页头显示同步失败原因与「重试」，侧栏/页尾在远端模式改为「退出登录」与账号邮箱。

### 关键决策
- 本地缓存仍是同步数据源，远端是异步投递：界面即时、离线可继续排课，数据库约束仍是最终边界；不把整个 Store 改成异步，避免现有交互与测试一起重写。
- 远端模式完全不碰本地缓存文件，换账号不会残留上一位教练的数据。
- 队列是「至少一次」：重放安全由 `p_request` 幂等键、主键 upsert 和状态白名单共同保证。

- `public/icons/*`：由 `scripts/make-icons.mjs` 用 Edge 渲染 SVG 导出 PNG（192/512/maskable/180），`npm run icons` 可重复生成；不引入图像库。
- `public/sw.js`：`tempo-v1-shell` 存 HTML/manifest/图标，`tempo-v1-assets` 存构建产物；导航网络优先回落 `index.html`，`/assets`、`/icons` 缓存优先；跨域与 `/auth`、`/rest` 一律不接管；`activate` 清理旧版本并 `clients.claim()`；新版本默认等待，收到 `SKIP_WAITING` 才接管。
- `vite.config.ts`：`tempo-sw-precache` 插件在 `closeBundle` 时把 `dist/assets/*` 清单注入 `dist/sw.js`，首次访问即可离线，无需额外依赖。
- `src/services/pwa.ts`：网络状态、`beforeinstallprompt`、拒绝记忆（`tempo.install.dismissed`）、iOS/iPadOS 文字指引、更新提示与 `applyUpdate()`；`initPwa()` 只在生产构建或 `?sw=1` 时注册 SW，并返回清理函数（测试注入假 window）。
- `src/services/offline.ts`：`tempo.cache.v1` 按 `userId` 缓存整份 `Database`，读取时校验账号与结构，损坏即丢弃。
- `src/app/boot.ts`：拉取成功写缓存；失败时若本账号有缓存则用缓存启动并记录时间戳，否则抛错。
- `src/stores/tempo.ts`：新增 `cachedAt`；`replaceData(next, cached)`；远端离线时 `assertWritable()` 拒绝所有写操作（`OfflineWriteError` 重写 `toString`，视图 `String(e)` 不会出现 `Error:` 前缀）。
- `App.vue`：跳转链接、离线横幅、更新横幅、安装卡片、`main#main` 可聚焦；恢复网络时先补发队列、队列清空再拉快照；退出登录清缓存。
- `styles/workbench.css`：横幅、安装卡片、跳转链接与移动端布局。

### 关键决策
- 远端离线只读，而不是「先存后补发」：同步队列在内存中，刷新即丢；假成功比不让改更糟。要做离线排课得先持久化队列并处理冲突，留到后续。
- 预缓存清单在构建时注入，而不是安装时枚举：安装期无法知道带 hash 的文件名，首次访问后离线才算真正可用。
- 新版本等待用户确认，不在训练中途强制刷新。
- hash 路由下 `href="#main"` 会污染路由，跳转链接改为 `@click.prevent` 后手动聚焦。
