# Tempo 产品与前端评审 · 2026-11-13

方法：两位子代理独立评审设计与代码证据，结合工作区自动化测试及 Android USB 真机检查。

**产品定位：Tempo 是健身教练管理学员预约排课、追踪运动表现和核对套餐课时的日常工作台。**

现有版本具备私教排课和课后反馈的基础，适合继续做本地演示。下一版优先补齐「登记套餐 → 排课占用 → 完成扣课 → 查看余额和流水」，同时修复会让预约或课时记录失真的操作。训练表现目前主要依靠教练评分、学员用力反馈和备注，后续应增加可比较的训练数据。

## 发现与优先级

| 优先级 | 发现 | 证据与建议 |
|---|---|---|
| P0 产品缺口 | 无法查询学员购买、已上和剩余课时 | 真机档案仅显示「已完成」「有效预约」「最近训练」。当前数据结构也没有套餐、预约归属或流水。将课时放在档案首屏，并接入排课和完成两个入口。[数据结构](../src/types/index.ts#L3) · [档案](../src/views/Students.vue#L150) |
| P1 缺陷 | 排课日期或时间清空后，实时校验可能抛错 | 源码路径为清空输入 → `conflict` 调用 `draft()` → 无效日期调用 `toISOString()`。调用发生在捕获异常之前。先判断日期、时间和时长，再生成草稿，给字段就地提示。[排课表单](../src/views/Editor.vue#L62) |
| P1 规则缺口 | 未来课程可以标完成，统计却按开始时间排除 | 状态规则只校验流转，未限制时间。若将完成接入扣课，会有提前扣课的风险。建议所有入口与服务端统一禁止完成尚未开始的课程，允许补登过去课程。[状态规则](../src/services/booking.ts#L4) · [训练统计](../src/services/reviews.ts#L18) |
| P1 上线风险 | 远端写入失败后刷新，待同步操作可能丢失 | 远端先更新界面，提交队列驻留内存。套餐扣课应等待服务端事务确认，失败时保留可重试状态，刷新后重新查询结果。[同步队列](../src/stores/sync.ts#L15) |
| P1 产品缺口 | 评分能描述单节感受，无法比较动作进步 | 可选用力程度和评分覆盖数值得保留。建议先支持记录动作、组次、重量或时长，并在课后录入时显示上次同一动作的数据。[训练反馈](../src/components/TrainingReview.vue) |
| P2 缺陷 | 未保存的训练反馈可在返回时静默丢失 | 源码中课程抽屉只跟踪排课字段，评分和笔记由独立组件保存。把反馈的修改状态纳入返回和关闭确认。[课程编辑器](../src/views/Editor.vue#L35) · [反馈表单](../src/components/TrainingReview.vue#L8) |
| P2 真机体验 | 首屏主要是汇总和日期控件，时间轴露出较少 | 真机首屏只有早晨空档。「今日 0 节」「已安排妥当」与「需要处理 4」同时出现，状态容易被误读。把今日任务拆成下一节、待确认和待完成，提供「跳到下一节」，合并重复日期。 |
| P2 真机体验 | 移动端仍提示使用「左侧列表」，部分按钮难读 | 手机列表下方保留桌面占位文案。档案「现在排课」为荧光浅绿文字配白底，截图上对比弱。移动端移除占位区，按钮用深色文字，并实测文字对比和 TalkBack。 |
| P2 信息层级 | 训练回顾在课史之后，评分记录再折叠一层 | 学员课史增长后，教练越难看到训练变化。在档案首屏显示最近训练摘要，详细记录按需展开。[学员档案](../src/views/Students.vue#L238) · [训练回顾](../src/components/TrainingStats.vue) |

课表作为默认入口、学员档案直接排课、课程类型色与文字状态分离，都符合私教高频操作。手机底部的「课表 / 学员 / 新建课程」容易找到。现有深色与荧光绿的识别度可以延续，将强调色优先给当前导航、待处理操作和余额提醒。

## 套餐课时 MVP

**学员档案**在身份和下一节之后显示套餐卡。例如「私教 12 节 · 已上 7 · 剩余 5」，下一行注明「其中已占用 2 节，还可约 3 节」。空状态给「登记套餐」，余额低时给「续购」。有多份套餐时逐份显示用途、有效期和余额，历史套餐可展开查看。

**排课**选定学员和课程类型后显示匹配套餐。单份匹配时默认选中，多份匹配时建议最早到期的套餐，并允许改选。体验课或单次课可显式选「不计套餐」。仅套餐预约校验余额，已耗尽或不适用时说明原因并提供登记或换套餐入口。

**完成**在课程详情和首页使用同一个操作，显示将扣哪份套餐及扣后余额。完成后可立即填写训练反馈，跳过或修改评分不改变课时。课程详情可打开扣课流水，显示时间、套餐、变化节数和操作者。

| 状态或操作 | 建议规则 |
|---|---|
| 登记与续购 | 每次购买独立建档，保存学员、套餐名、购买日期、总节数、适用课程和可选有效期。首版记录线下成交 |
| 待确认与确认 | 待确认不占课，确认时占 1 节。直接创建已确认预约也占 1 节。剩余 = 总节数减已扣，可约 = 剩余减已占用 |
| 改期、换人或换课型 | 校验新课日期和套餐是否仍匹配。变更原占用与新增占用一次提交，失败保留原预约 |
| 完成与取消 | 完成释放占用并扣 1 节。取消释放占用。暂不自动扣缺席或迟取消 |
| 更正 | 提供带原因的撤销扣课操作，同时明确更正后的课程状态。保留原扣课及冲正流水 |
| 历史迁移 | 旧课保留为未关联，登记历史套餐时可单独录入期初已用节数。避免将学员历史完成总数自动计入套餐 |

实现时用套餐购买记录、预约归属和课时流水支撑展示。完成状态与扣课必须在同一事务内提交。用预约 ID 约束重复扣课，在同一套餐的余额校验中防止两台设备争抢最后一节。远端无连接时显示上次余额与同步时间，并保持套餐操作只读。套餐、预约和流水均按教练归属校验。

## 下一版验收

| 场景 | 验收结果 |
|---|---|
| 登记 12 节，期初已用 7 节，再确认两节 | 档案显示总 12、已上 7、剩余 5、占用 2、可约 3 |
| 完成其中一节，重复点击或请求重试 | 仅产生一次扣课。档案显示已上 8、剩余 4、占用 1、可约 3 |
| 取消另一节，或改期到套餐到期后 | 取消后剩余仍为 4、可约恢复 4。超期改约有清楚提示，原预约保留 |
| 两台设备尝试确认最后一节 | 只有一笔成功，另一笔收到可处理的余额提示 |
| 撤销误扣、刷新、重新登录 | 流水能追溯原记录和更正原因，课程和余额一致 |
| 导入旧数据、录入体验课 | 历史课程与单次课可查，套餐余额按实际关联计算 |
| 真机完整流程 | 用当前构建在 Android 完成登记、排课、冲突提示、完成、反馈、刷新复查。同步恢复后补跑 Web E2E 与双账号检查 |

建议按「排课异常和状态规则 → 套餐登记与扣课闭环 → 训练指标与移动端层级」排期。首轮试用记录从学员档案查到余额的时间、每次完成课程后的扣课正确率，以及课后补评和训练记录的完成情况。
