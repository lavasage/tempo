## 假设
- M1 保持现有新建默认 confirmed；pending 必须先 confirmed 才能 completed。完成是手动动作，本轮不新增“必须等到预约结束”的业务门槛。
- 时间 UTC 存储，展示/筛选用浏览器时区；固定门店时区在 M2 决定，不声称多时区已解决。
- 本地多标签陈旧检测是防误覆盖，不是服务端并发保证。
- 前端 App 技术路径待设备能力需求确认：先维持 Vue 移动 Web/PWA，未来可评估原生容器；本轮不增加 Capacitor 等依赖。
## M3验收与业务口径
新增/编辑学员后能从档案直接排课；历史按日期及类型筛选；今日/自然周/月统计从课程派生；下一节与待办可直接操作；旧数据和评分功能回归。本轮不实施M4。

- 联系电话可留空，填写时接受7–15位数字及国际前缀；不假定号码唯一。
- 有效预约是尚未结束的pending/confirmed课程；已预约筛选仅含尚未结束的confirmed，待确认单独筛选。过期未完成仍保留在全部记录与待办中，不自动完成。
- 今日/本周数量按课程开始日计入，排除cancelled；本周为周一至周日。本月完成、累计完成和最近训练只计已手动完成且已开始的课程。
- 下一节优先显示正在进行的confirmed课程，否则展示最近一节未来confirmed；pending进入待处理。
- 课时账户仅设计，不显示推算余额、不扣课时。
- 远端离线只读：同步队列未持久化，离线写入会刷新即丢，因此 `assertWritable()` 直接拒绝并提示联网；本地演示不受影响。

## M4客户端（已完成代码，未联调）
- `src/services/remote/`：`config` 只在同时提供 URL 与 anon key 时启用远端；`session` 负责 GoTrue 登录/注册/续期/退出；`client` 走 PostgREST 与 RPC，并把约束错误翻成中文；`mapping` 做分钟↔时钟、快照↔`Database`、可用性↔RPC 参数；`repository` 是异步远端仓库。

- 本地模式完全不变：未配置环境变量时不出现登录页，数据仍写 `tempo.v1`，现有 79 项单测与 20 条 E2E 均跑此路径。
