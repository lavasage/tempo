## 第二批：套餐与可靠提交

**可靠提交已完成（2026-11-13 晚）。** 同步队列从内存数组改为落盘 outbox（`src/services/outbox.ts`）：每项带 `id/createdAt/attempts`，成功才出队，失败保留队首并记录尝试次数；`bootRemote` 启动时接回上次未提交的操作并继续推送，推送成功后重取一次快照对齐；队列按账号分键，退出登录只断开连接、不清队列。刷新、断网、崩溃不再丢操作。7 条队列单测覆盖出队/失败停住/重放去重/损坏存储降级/账号分键。

边界：队列是「至少一次」，重放依赖幂等键（预约创建用课程 id 作 `p_request`，状态变更与 upsert 可重放）。缺少「按请求 id 查询结果」的接口，服务端成功但响应丢失时界面会停在待同步，直到下次重放成功；接入扣课前需补该查询。

**套餐课时闭环已完成（2026-11-13）。** 按报告规则落到三层：

- 模型：`LessonPackage`（每次购买独立建档，含总节数、期初已用、购买日、可选到期日）、`LessonTransaction`（purchase/consume/refund/adjust）、`Booking.package_id`（为空即「不计套餐」）。旧数据缺字段时按空读取，不触发迁移提示；旧课保持未关联，不从历史完成数推算余额。
- 余额只有一个来源：套餐流水求和。`剩余 = Σ流水`，`已上 = 总节数 − 剩余`，`占用 = 已确认且未完成的课程数`，`可约 = 剩余 − 占用`。待确认不占课；完成把占用转成 −1；取消只释放占用、不写流水；冲正 +1 且保留原扣减。
- 本地原子服务 `src/services/packages.ts`：登记、匹配、扣减、冲正、流水查询全部是纯函数，由 store 一次提交。9 条单测覆盖 12/7/2 场景、占用与释放、重复扣减、重复冲正、类型/到期/余额校验、可约排序。
- 服务端 `0007_lesson_packages.sql`：`package_save`（客户端生成 id，重放幂等）、`booking_create`/`booking_update` 带 `p_package`、`booking_set_status` 在**同一事务**里扣课、`lesson_revert` 冲正、`snapshot` 带出套餐与流水。套餐级咨询锁 + 复合外键 `(package_id, coach_id)` 挡跨教练关联；扣减以课程 id 做幂等键。
- 界面：学员档案首屏套餐卡（总/已上/剩余/占用/可约、到期、余额低给续购）、排课抽屉按学员+类型+日期匹配并默认选最早到期、完成按钮显示「扣 1 节」、课程抽屉显示扣课流水与带原因撤销。
- 验收：PGlite 36 项（含最后一节争抢、过期改期、跨教练、快照结构、登记幂等）、业务单测 128 项、E2E 覆盖登记/扣课/冲正/不计套餐。

已知边界：客户端仍先本地乐观写入再排队推送，服务端若因余额不足拒绝，界面会停在待同步并展示服务端原因；补齐「按请求 id 查询结果」的接口前，不宣称强一致。
