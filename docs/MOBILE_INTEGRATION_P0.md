## 不可改变的业务约束

- UTC存储、当地日期显示；半开时间区间，取消释放占用，已完成仍保留历史时间占用。
- pending只能确认/取消；confirmed只能完成/取消；完成不得早于开始；终态不能普通编辑恢复。
- 业务关联与coach_id校验、RLS及服务端冲突校验持续有效。客户端过滤不构成权限。
- 评分不等于出勤或扣课；评分修改不得影响余额。现有历史不自动归属新套餐。
- 本地先持久化后更新Store；不能用重置解决迁移或读取错误。
- 现有评分1–5与口述用力1–10独立，未评分不算零分，多学员平均不解释为能力趋势。

## 待确认规则（到对应阶段再确认，不阻止体验规划）

1. 缺席与迟取消是否收费、谁可更正；不能直接新增状态导致旧规则变化。
2. 套餐经营闭环在新任务书列为可选P5，上一评审列为高优先级：本轮按最新“先体验”执行，不删除既有套餐设计。
3. 跨时区使用采用教练固定时区还是设备时区；当前客户端按设备时区。
4. 训练记录单位首版是否固定kg/次/秒，分配后计划是否允许生成新版本替代未来课程。

每阶段交付修改清单、业务影响、测试证据、限制、回退步骤。保留现有未提交改动，先建立阶段快照，不直接reset/覆盖。纯视觉回退仅恢复本阶段文件；数据库采用前向兼容迁移，备份恢复在隔离环境演练，不删真实新记录回退。尚无通用新模块开关，需在模块实施时明确默认关闭策略，不假称已有灰度平台。
