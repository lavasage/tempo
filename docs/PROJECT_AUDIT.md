# PROJECT AUDIT — Milestone 1
日期：2026-11-11。范围：全部 src、配置、现有单测/E2E、README 和开源迁移记录；不是生产环境认证。

## 现状与证据
- Vue 3 + TS strict + Vite/Tailwind、Pinia、Vue Router hash 路由；Lucide 图标。未使用 Supabase 或其他远程 API。
- main.ts 装配 /、/students、/create、/booking/:id；三个视图，反馈/统计两个复用组件。router/layouts 等目录为空，不视为功能实现。
- Repository 同步读写 localStorage 整个快照；Store 先保存后更新 UI；Service 实现区间冲突和评分；视图仍包含表单组装、日历过滤等逻辑。
- 已实现：日期切换、滚动七天视图、创建/编辑/取消/手动完成、学员只读列表/搜索、课后反馈与统计、刷新保留已保存数据。
- 部分实现：日历是时间排序列表而非按比例时间轴；周视图不是自然周；空闲是固定整小时建议；已完成只读仅由 UI 控制；状态转换缺少明确白名单。
- 未实现：月历、营业/工作时间、休息/缓冲、学员新增编辑、课时账户、完整工作台、认证/RLS/服务端并发、PWA、原生 App。
- 基线：18 项单测，2 套 Edge 尺寸 E2E 仅覆盖评分。未证明创建、编辑、取消全流程，也未验证 Safari/Android 实机。

## 发现的问题（修复前）
| 优先级 | 证据 | 风险 / 处理 |
|---|---|---|
| P0 | changeStatus 只阻止终态 | pending 可直接 completed，confirmed 可回 pending；M1 白名单修复 |
| P0 | saveBooking 只做时间/非空检查 | 可绕过 UI 修改终态、状态、归属和未知学员；M1 服务层保护 |
| P0 | Store load 失败后 seed，仍允许 commit | 损坏真实数据可能被演示数据覆盖；M1 错误时阻止业务写入，仅显式重置恢复 |
| P1 | 初始 seed 不保存 | 刷新未修改过的课程详情会因 UUID 改变失效；M1 初始化持久化 |
| P1 | 日历只筛 start_at 当天 | 跨午夜课程次日不可见，空闲建议遗漏占用；M1 区间相交过滤 |
| P1 | 课程变更没有历史事件 | 无法追溯创建/编辑/状态；M1 同快照写入 before/after 事件 |
| P1 | 编辑页保存返回 / | 跳回今天丢失所选日期；M1 query 保留日期 |
| P1 | 快照无陈旧检查 | 多标签覆盖彼此写入；M1 检测旧快照并要求刷新，跨设备事务留 M4 |
| P2 | 多文件单行压缩；无运行时深层验证 | 可维护性差；仅整理本轮涉及业务文件，增加结构/关联校验 |
| P2 | 无加载状态、防重复提交通用层 | 本地同步写入暂不需异步骨架，M4 异步接入统一处理 |

## 风险与优先级
M1 修复数据完整性及基线回归；M2 时间可用性/日周月；M3 学员与工作台；M4 Auth/RLS/数据库事务；M5 PWA/实机与试用。没有后端隔离、备份与并发约束前，只适合隔离测试数据试用。业务目标 10 秒/3 次操作尚未实测。
